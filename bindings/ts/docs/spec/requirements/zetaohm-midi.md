| <a id="req-ts-ci-002"></a>REQ-TS-CI-002 | After a Property Exchange Get, Set or Subscription event, the Device shall answer it through the one-chunk Responder of the C ABI with a status and, for a Get, the Property Data of the program (the ResourceList of the configuration for a Get of ResourceList), and throw RejectedError when no request is pending. |  |  | `Discovery, PE Get and Set between two devices` |  |

Each Profile event of receive (Reply to Profile Inquiry, Profile report, Set Profile, Profile Details Inquiry and Reply, Profile Specific Data) shall carry its Profile fields: Device ID, Group, Profile ID, report kind, On or Off, Channels, Inquiry Target, notification, the enabled and disabled Profile IDs of a Reply to Profile Inquiry, and the data. Each Process Inquiry event of receive shall carry the Device ID, the Group, the MIDI Message Report capability and the bitmaps. | <a id="req-ts-file-001"></a>REQ-TS-FILE-001 | The package shall give a MIDI Clip File reader that gives each message with its section and absolute ticks, and a writer that checks each call against the rules of zmidi-file, makes its buffer larger when the clip needs it, and gives the bytes of the clip (M2-116). |  |  | `minimal clip`, `write and read back`, `a long clip grows its buffer`, `bad clip input` |  |
| <a id="req-ts-io-001"></a>REQ-TS-IO-001 | The package shall give a MIDI 1.0 byte stream reader that gives UMPs on one Group in the MIDI 1.0 or MIDI 2.0 Protocol (zmidi-io BytesToUmp, M2-104 Appendix D), and a writer of MIDI 1.0 bytes from UMPs with optional running status and a status refresh (zmidi-io UmpToBytes, M1). feed shall read many bytes in one C call (zmidi_bytes_to_ump_feed, OPT-035) and give the same UMPs as one push for each byte. |  |  | `MIDI 1.0 bytes to UMP with running status`, `bytes to MIDI 2.0 UMP and SysEx`, `UMP to bytes with running status and refresh`, `bad values and a freed object`, `feed of a long stream gives the UMPs of push` |  |
| <a id="req-ts-mem-001"></a>REQ-TS-MEM-001 | Each object of the package shall own the WASM memory of its C state and give it back with free, or when the garbage collector removes the object. The hot paths (BytesToUmp, UmpToBytes, BleReader, BleWriter, UsbLink) keep one scratch block for the arguments of their calls, and a larger call makes it larger. |  |  | `bad values and a freed object`, `a large transfer after a small one` |  |

| <a id="req-ts-net-003"></a>REQ-TS-NET-003 | The authentication events shall give the codes and values of the C ABI: authRequested the method and the Authentication State; authFailed the method, with NET_AUTH_USERNAME_NOT_FOUND for an unknown Username, and the failure count; credentialsError the problem with the credentials; established the method (0 for none).
