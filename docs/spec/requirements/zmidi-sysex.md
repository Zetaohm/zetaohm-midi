# Requirements — zmidi-sysex

| Id | Requirement | Part of | Source | Verified by | Decided by |
|---|---|---|---|---|---|
| <a id="req-dc-001"></a>REQ-DC-001 | The crate shall read Universal Real Time Sub-ID#1 04H as Device Control, and shall read and write Master Volume (Sub-ID#2 01H) and Master Balance (02H), each with the Device ID and a 14-bit value sent LSB first: volume 0 is off, balance 0 is hard left and 3FFFH is hard right (center 2000H, AMB-M1-53). |  | m1 | `master_volume_and_balance_bytes` |  |
| <a id="req-dc-002"></a>REQ-DC-002 | The crate shall read and write Master Fine Tuning (Device Control Sub-ID#2 03H): the Device ID and a 14-bit value sent LSB first, given as the signed offset from 8192 (-8192 to +8191) where 8192 steps are 100 cents from A440, the scale of Channel Fine Tuning (AMB-CA-025-02). |  | ca-025 | `master_fine_tuning_ca_025_table` |  |
| <a id="req-dc-003"></a>REQ-DC-003 | The crate shall read and write Master Coarse Tuning (Device Control Sub-ID#2 04H): the Device ID, an LSB and an MSB; the value is the MSB minus 64 semitones from A440 (-64 to +63). The writer shall write LSB 0, and the reader shall ignore the LSB (AMB-CA-025-01). |  | ca-025 | `master_coarse_tuning_ca_025_table` |  |
| <a id="req-dc-004"></a>REQ-DC-004 | The Device Control messages shall be in the Cargo feature `device-control`, which is in `full` (on by default); without it the reader gives them raw and the crate has no Device Control type. |  | m1 | `device_control_is_in_the_default_features` |  |
| <a id="req-gm-001"></a>REQ-GM-001 | The crate shall read and write the General MIDI System messages: GM1 System On (Sub-ID#2 01H), GM System Off (02H) and GM2 System On (03H), each as F0H 7EH, the Device ID, Sub-ID#1 09H, the Sub-ID#2, F7H. The reader shall give another Sub-ID#2 under 09H as a raw Universal message. |  | m1; rp-024; rp-003 | `general_midi_system_messages_bytes` |  |
| <a id="req-gm-002"></a>REQ-GM-002 | The General MIDI System messages shall be in the Cargo feature `gm`, which is in `full` (on by default); without it the reader gives these messages raw and the crate has no General MIDI type. |  | m1 | `gm_is_in_the_default_features` |  |
| <a id="req-inq-001"></a>REQ-INQ-001 | The crate shall read and write the Identity Request (Universal Non-Real Time, Sub-ID#1 06H General Information, Sub-ID#2 01H) with its Device ID. |  | m1 | `identity_request_bytes` |  |
| <a id="req-inq-002"></a>REQ-INQ-002 | The crate shall read and write the Identity Reply (Sub-ID#1 06H, Sub-ID#2 02H): the Device ID, the Manufacturer ID (three bytes when the first byte is 00H, else one byte), the device family code and the family member code (14 bits each, LSB first) and four bytes of software revision level. |  | m1 | `identity_reply_one_and_three_byte_ids` |  |
| <a id="req-inq-003"></a>REQ-INQ-003 | The crate shall give a responder function: from a received Identity Request, the own Device ID and the identity that the caller gives, it writes the Identity Reply when the request has Device ID 7FH or the own Device ID, and gives nothing otherwise. The reply carries the own Device ID, also for a request with 7FH (AMB-M1-31). |  | m1 | `responder_answers_all_call_and_own_id` |  |
| <a id="req-inq-004"></a>REQ-INQ-004 | The Identity Request and Reply shall be in the Cargo feature `inquiry`, which is in `full` (on by default); without it the reader gives these messages raw and the crate has no inquiry type. |  | m1 | `inquiry_is_in_the_default_features` |  |
| <a id="req-sx-001"></a>REQ-SX-001 | The crate shall take one complete System Exclusive message as bytes, with or without the F0H start byte and the F7H end byte, so that the same reader serves a byte stream and the payload of UMP System Exclusive (7-bit) packets. A message with a data byte above 7FH, an F0H or F7H inside, or no ID byte shall give an error, and the reader shall never panic. |  | m1 | `framing_with_and_without_f0_f7`, `prop_reader_never_panics` |  |
| <a id="req-sx-002"></a>REQ-SX-002 | The crate shall classify the first data byte of a System Exclusive message: 00H starts a 3-byte Manufacturer ID, 01H to 7CH is a 1-byte Manufacturer ID, 7DH is Non-Commercial, 7EH is Universal Non-Real Time and 7FH is Universal Real Time. It shall give the ID (as zmidi-ump ManufacturerId for a manufacturer) and the bytes after it. |  | m1 | `ids_follow_table_vii` |  |
| <a id="req-sx-003"></a>REQ-SX-003 | A writer of a manufacturer System Exclusive message shall reject the Manufacturer IDs 00H (one byte) and 00H 00H 00H, which M1 reserves; a reader shall give such a message to the caller as it is (AMB-M1-58). |  | m1 | `writer_rejects_reserved_manufacturer_ids` |  |
| <a id="req-sx-004"></a>REQ-SX-004 | The crate shall read and write the Universal System Exclusive header: the ID (7EH or 7FH), the Device ID, the Sub-ID#1 and, only for the families that define one, the Sub-ID#2 (Non-Real Time 04H to 09H, Real Time 01H, 03H, 04H, 05H, 08H; AMB-M1-29), and shall give the bytes after the header. It shall give each Sub-ID#1 and Sub-ID#2 value of Table VIIa a name. |  | m1 | `universal_header_follows_table_viia` |  |
| <a id="req-sx-005"></a>REQ-SX-005 | The crate shall give the Device ID (00H to 7FH) of each Universal message, and a function that is true when a received Device ID is 7FH (all devices) or equal to the own Device ID that the caller gives (AMB-M1-30), and the constant 7FH for a writer that addresses all devices. The MIDI-CI rules for Sub-ID#1 0DH stay in zmidi-ci. |  | m1; rp-003; rp-024 | `device_id_all_call_and_own` |  |
| <a id="req-sx-006"></a>REQ-SX-006 | The crate shall have one reader that gives each Universal message of an enabled part as its typed message, and gives every other Universal message as the raw header and bytes: an unknown Sub-ID#1 or Sub-ID#2, a part that is not enabled, MIDI-CI (Non-Real Time 0DH) and the families of later parts (AMB-M1-60). A manufacturer or Non-Commercial message is given with its ID and bytes. |  | m1 | `unknown_sub_ids_are_raw`, `midi_ci_is_raw` |  |
| <a id="req-sx-007"></a>REQ-SX-007 | Each writer of the crate shall write one complete message, from F0H to F7H, into a caller buffer and give its length, or give an error with the needed length when the buffer is too small; then the buffer content is not defined. A writer shall reject a value out of the range of its field. |  | m1 | `writers_report_overflow` |  |
| <a id="req-tun-001"></a>REQ-TUN-001 | The crate shall read and write the 3-byte MIDI Tuning frequency word: the equal-tempered semitone below the frequency (7 bits) and the fraction above it in 1/16384 of 100 cents (14 bits, MSB first). The word 7FH 7FH 7FH shall be "no change" and not a frequency. Frequency data shall be written only in the System Exclusive formats of the MIDI Tuning messages. |  | m1; mts | `frequency_word_examples`, `prop_frequency_word_round_trip` |  |
| <a id="req-tun-002"></a>REQ-TUN-002 | The crate shall read and write the Bulk Tuning Dump Request (Non-Real Time 08H 00H: Device ID, program) and the Bulk Tuning Dump Request with a bank (08H 03H: Device ID, bank, program); program and bank are 0 to 127 (AMB-MTS-04, AMB-MTS-05). The bank form has a Device ID (AMB-MTS-01). |  | m1; mts | `dump_requests_with_and_without_bank` |  |
| <a id="req-tun-003"></a>REQ-TUN-003 | The crate shall read and write the Bulk Tuning Dump (08H 01H: Device ID, program) and the Key-Based Tuning Dump (08H 04H: Device ID, bank, program), each with a 16-byte name, 128 frequency words in key order from 0 to 127 and a checksum. The reader shall give the words as an iterator over the message bytes; the writer shall accept "no change" for any key. |  | m1; mts | `key_based_dumps_round_trip` |  |
| <a id="req-tun-004"></a>REQ-TUN-004 | The checksum of a tuning dump shall be the XOR of all bytes after F0H and before the checksum, AND 7FH. Each writer shall write it. The reader shall check it for the dumps 04H, 05H and 06H; for the dump 01H it shall give the result of the check to the caller and not reject the message for it (AMB-M1-46, AMB-MTS-02). |  | m1; mts | `checksum_rules` |  |
| <a id="req-tun-005"></a>REQ-TUN-005 | The crate shall read and write the Single Note Tuning Change (Real Time 08H 02H: Device ID, program) and the Single Note Tuning Change with a bank (08H 07H in both the Real Time and the Non-Real Time forms: Device ID, bank, program), each with a count of 1 to 127 and that many sets of key and frequency word. The reader shall reject a length that does not match the count, and shall give the header type of the 07H form (AMB-MTS-06). |  | m1; mts | `single_note_changes` |  |
| <a id="req-tun-006"></a>REQ-TUN-006 | The crate shall read and write the Scale/Octave Tuning Dumps (Non-Real Time 08H 05H and 08H 06H: Device ID, bank, program, a 16-byte name, the 12 offsets from C to B and a checksum). An offset of the 1-byte format is the byte minus 64 cents; an offset of the 2-byte format is a 14-bit value, MSB first, as the signed offset from 8192 in steps of 100/8192 cents (AMB-MTS-08). |  | mts | `scale_octave_dumps` |  |
| <a id="req-tun-007"></a>REQ-TUN-007 | The crate shall read and write the Scale/Octave Tuning 1-byte form (08H 08H) and 2-byte form (08H 09H), each in the Real Time and the Non-Real Time forms with the header type given: the Device ID, the 3-byte channel field as a 16-bit channel set, and the 12 offsets of REQ-TUN-006. The writer shall write the 5 reserved bits of the channel field as 0, and the reader shall ignore them (AMB-MTS-07). |  | mts | `scale_octave_forms_and_channels` |  |
| <a id="req-tun-008"></a>REQ-TUN-008 | The MIDI Tuning messages shall be in the Cargo feature `tuning`, which is in `full` (on by default); without it the reader gives them raw and the crate has no tuning type. |  | m1 | `tuning_is_in_the_default_features` |  |
