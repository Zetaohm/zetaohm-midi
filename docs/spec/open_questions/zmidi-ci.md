| <a id="oq-ci-001"></a>OQ-CI-001 | **Responder-only build: what to do with a reply that only an Initiator expects**<br>A Device built with the feature initiator off (REQ-CI-TIER-002, OPT-049 step 8) has no Initiator<br>role. What does it do with a message that only an Initiator expects: Reply to Discovery (0x71), Reply to<br>Endpoint Information (0x73), Reply to Profile Inquiry (0x21), Reply to PE Capabilities (0x31), Reply to Process<br>Inquiry Capabilities (0x41), Reply to MIDI Message Report and End of MIDI Message Report (0x43, 0x44)?<br><br>M2-101 does not say (AMB-M2-101-27). 5.11 (PDF page 35): the NAK is the response to any message that a<br>Device does not understand, for example a reply to a MIDI-CI message that the Device does not support. Appendix F<br>(PDF page 74) asks only to respond to Discovery and to Invalidate MUID, and to be able to send a NAK.<br><br>ACK and NAK stay readable in both roles (an Initiator can send NAK 0x20 Terminate, Table 16; ACK flow control),<br>and the peer table stays (the Receivable Maximum SysEx Message Size and Message Version of the Initiator come<br>from its Discovery, DEC-011 D-11).<br><br>Options:<br>(a) ignore the reply: no event and no NAK (a reply is not a request, so no NAK loop can start);<br>(b) NAK 0x01 Not Supported (the literal reading of 5.11);<br>(c) an event with the raw Sub-ID#2 and body, so that the application can act.<br>Recommendation: (a), confidence 75%.
