# DEC-017 — Size tiers: all features on by default, opt-out Cargo features per crate

**Status:** accepted

Each crate and the `midi` facade get a feature set `full`, on by default (`default = ["full"]`). With
all features on, the library gives its full MIDI 2.0 functionality. A user sets
`default-features = false` and selects features to make a smaller build. `zlib` (DEC-PE-001) and
`auth` (DEC-013) are not in `full`: they stay opt-in.

Cargo features go only at the central dispatch points, where one function reaches all the code of a
group: `Ump::parse`, the MIDI-CI message handler, the PE header parser and the USB configuration.
Elsewhere the linker removes unused code; word-level APIs and a const USB configuration are the
other tools. The feature names in OPT-052 are provisional: each crate confirms its
names when its step of the plan lands, as an addendum to this decision. Confirmed for `zmidi-ump`
(2026-10-20): `utility`, `system-common`, `channel-voice1`, `channel-voice2`, `sysex7`, `data128`,
`flex-data`, `ump-stream`, all in `full`. Until a crate gets its own features, it asks for
`zmidi-ump/full`, so its behaviour does not change.

A feature that is off still obeys the specification (DEC-001):

- UMP: a Message Type whose feature is off parses as `Ump::Unknown` with its raw words and its
  length (Table 4), as a reserved Message Type does (M2-104 2.1.4). `MessageType::is_decoded()`
  (`const fn`) gives false for a Message Type that this build does not decode, so a caller can
  tell "off in this build" from "reserved".
- MIDI-CI: the Discovery category bits give only the compiled categories. With Profiles off, every
  Profile message, Profile Inquiry included, gets a NAK (M2-101 5.11), as with Profiles off in
  `DeviceConfig` at run time; the 0/0 Profile Inquiry Reply of 7.13 is optional and not sent
  (correction of 2026-10-20; AMB-M2-101-26). With Process Inquiry off, its
  messages get a NAK (5.11).

The goal is that the smallest build of each job uses 1.0x the flash and RAM of the smallest other
library for the same job (midi2 C99, AM_MIDI2.0Lib, `tusb_ump`), measured with `tools/size-probe`
and `tools/lib-compare`.

## Context

The plan is for adoption, not only for FLXS1. Users compare the smallest
build that does their job. Measurements of 2026-10-19 and
2026-10-20: the message layer reaches 1.0x with word paths; the USB
class (23,852 B), MIDI-CI (16,500 B) and PE (30,096 B) are 3.6x to 20x. Before this decision only
`zlib` and `auth` were features, both opt-in. A gate on the CI category check alone saved 24 B; a
gate on each message arm saved 3,736 B, so features must remove code at the dispatch points.

## Consequences

- Each crate gets a feature matrix. CI runs the tier builds and the full build on every run, and
  `cargo hack --each-feature` plus `--feature-powerset --depth 2`, split with `--partition M/N`
  across parallel jobs, each with its own target directory. Each combination is a host test and a
  check for `thumbv7em-none-eabihf` (DEC-002).
- `scripts/size-check.py` keeps a flash and RAM budget for each job; a change that lands lowers the
  budget.
- Code that passes UMPs on (routers, transports, `UmpToBytes`) keeps working in any feature set,
  because a type that is off is still a packet with its length.
- Cargo unifies features across a build: a dependency that turns a feature on changes `Unknown` to
  a typed value for every crate in that build.
- A crate forwards the features of the crates below it; the work goes in dependency order
  (`zmidi-ump`, `zmidi-io`, `zmidi-ci`, `zmidi-ci-pe`, `zmidi-usb`).

## Alternatives

- An error from `Ump::parse` for a type that is off (as the Rust `midi2` 0.11.1 crate does): rejected,
  because pass-through code drops the packet and the caller loses the packet length. midi2 C99,
  AM_MIDI2.0Lib and ni-midi2 keep the words of a packet they do not decode.
- Opt-in features (default off): rejected, because a default build then lacks MIDI 2.0 functions, and
  the goal is full functionality when all features are on.
- `zlib` and `auth` in `full`: rejected; they add a dependency and state (DEC-013, DEC-PE-001).
- Features at every module: rejected; the linker already removes code that nothing calls.

## Verification

- `cargo hack` feature matrix in CI (host tests and the bare-metal check for each combination).
- Tests for a build with each Message Type off: `Ump::parse` gives `Unknown` with the right length,
  and `MessageType::is_decoded()` gives false.
- MIDI-CI tests with Profiles and Process Inquiry off: the Discovery category bits and the NAKs.
- `scripts/size-check.py` budgets for each job.
