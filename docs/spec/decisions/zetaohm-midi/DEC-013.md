# DEC-013 — zmidi-net authentication: sha2 behind the Cargo feature auth, off by default

**Status:** accepted

The SHA-256 Authentication Digest of M2-124-UM v1.0.1 (6.9 "Invitation with Authentication", 6.10
"Invitation with User Authentication") uses the RustCrypto crate `sha2` (0.11) with
`default-features = false` (no alloc, no_std) and its feature `zeroize`, which clears the hash state
on drop (REQ-NET-AUTH-011; it adds the crate `zeroize`, 2026-10-17). The dependency and the authentication commands are
behind a Cargo feature `auth` of `zmidi-net`, off by default. Without the feature a Client does not set
the capability bits D0 and D1 of the Invitation, and a Host does not ask for authentication.

## Context

Authentication is optional on
both sides: a Client declares it in the Capabilities field of the Invitation (6.4, bits D0 and D1),
and a Host sends "Invitation Reply: Authentication Required" only when the Client set D0 (6.7). A
hand-written SHA-256 was rejected: cryptographic code is safer from a reviewed crate.

## Consequences

- A default build has no cryptographic dependency.
- The gates build zmidi-net for the bare-metal target with and without `auth`, and run the tests
  with all features. The digest examples of 6.9 and 6.10 are test vectors.
