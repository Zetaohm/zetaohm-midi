# DEC-011 — MIDI-CI requirement choices D-5 to D-18 (review of 2026-10-15)

**Status:** accepted

The `zmidi-ci` requirements resolve these gaps and conflicts of M2-101-UM
v1.2.1, M2-102-U v1.1 and M2-103-UM v1.2 (the ambiguity register):

- D-5 A Discovery with the responder's own MUID as Source is an echo, and is
  ignored, when it is identical to the last Discovery this device sent; any
  other case is a MUID collision (REQ-CI-MUID-012).
- D-6 Collision: Option A when the MUID was not used in a Transaction, else
  Option B (5.9.1).
- D-7 NAK Status Code where the specification gives none: 0x03 for a Device
  ID or address that is not valid or not in use; 0x04 for a Profile or
  Inquiry Target that is not supported; 0x00 for other cases.
- D-8 A received Message Format Version 0x00 is processed as version 0x01;
  the writer never writes 0x00.
- D-9 Message Version/Format: bits 6-5 reserved, bits 4-0 minor version.
- D-10 Device ID on reception: each message accepts the values its table
  allows; Property Exchange also accepts 0x0F (8.2 text); any other value
  gets NAK 0x03.
- D-11 An ACK or NAK larger than the receiver's Receivable Maximum SysEx
  Message Size has its Message Text shortened to fit; 128 bytes applies when
  the size is not known.
- D-12 The reply to Inquiry: Endpoint Information is "shall" (5.5.2).
- D-13 The six Profile messages that M2-102 Table 6 marks "Mandatory" are
  "shall"; this is an accepted exception to the DEC-005 rule that a table does
  not raise a "should".
- D-14 The crate gives Profile report events; the application keeps the
  Profile lists of other Devices.
- D-15 The M2-103 Chunk framing rows belong to `zmidi-ci` (DEC-006).
- D-16, D-17, D-18 The Profile details, PE framing and editorial readings of
  the register are accepted as written in the requirements.

## Context

An independent review of the 243 MIDI-CI requirements listed these choices.

## Consequences

- The requirements named in each register row carry these readings, and the
  register marks the items RESOLVED.
- Interop notes: JUCE treats every own-MUID Discovery as a collision and NAKs
  every ACK with 0x00; the Workbench NAKs version 0x00 and PE Device ID 0x0F.
