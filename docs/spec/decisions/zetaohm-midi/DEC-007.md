# DEC-007 — zmidi-ci-pe has no alloc: fixed header buffer, streamed Property Data

**Status:** accepted

`zmidi-ci-pe` meets DEC-002 with no `alloc`:
- The Header Data JSON of a Property Exchange message is collected in a
  fixed-capacity buffer (const generic size) and parsed by a small no-alloc
  JSON parser that reads only the header properties the crate needs; it never
  builds a document tree.
- Property Data is not collected: each chunk's Property Data bytes go to the
  caller as they arrive (an iterator or a caller buffer), in chunk order.
- Mcoded7 decoding and encoding are streamed. zlib (M2-103 compressed data)
  is streamed with caller-supplied buffers (for example the no_std
  `miniz_oxide` core, which needs no alloc).
- Writers fill caller buffers and return an overflow error when a buffer is
  too small.
- A header larger than the buffer gives an error (and, where M2-103 defines
  a status reply for it, that reply), never a panic or a heap use.

## Context

DEC-002 forbids `alloc` in the core API and says a member that cannot meet the
rule records an open question. The user decided on 2026-10-14, before the
M2-103 catalogue was complete, that Property Exchange uses this streaming
design instead of an `alloc` feature.

## Consequences

- The caller chooses the header buffer size; a product states the largest
  header it accepts.
- Resource contents (for example DeviceInfo or ChannelList JSON bodies) are
  the application's to build or parse; the crate gives the bytes and the
  header fields.
- The M2-103 catalogue "No-alloc impact" section must be checked against this
  design; a rule that needs the whole body in memory is a reason to revisit
  this decision with the user.

## Alternatives

- An optional `alloc` feature with whole-message JSON handling: rejected by
  the user; it would need a DEC-002 exception.
- An open question, decided after the catalogue: rejected by the user.

## Verification

`zmidi-ci-pe` builds for `thumbv7em-none-eabihf` with no default features, and
its tests read and write multi-chunk Property Exchange messages larger than
any internal buffer.
