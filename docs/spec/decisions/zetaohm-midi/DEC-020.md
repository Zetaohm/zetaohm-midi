# DEC-020 — BLE adapter zmidi-ble-trouble on trouble-host 0.7

**Status:** accepted

The `trouble-host` adapter of DEC-016 is the Cargo crate `crates/zmidi-ble-trouble`, a workspace member and not a
specdev member (as the USB adapters, DEC-015). It uses `trouble-host` 0.7 and `bt-hci` 0.9, the pair of
`esp-radio` 1.0.0-beta.1. It is `no_std` with no `alloc` (DEC-002) and has no protocol logic (DEC-004).

Shape:
- `MidiService::add` adds the MIDI Service to the caller's `AttributeTable`, so the firmware also adds GAP and its
  own services. There is no derive macro.
- The characteristic value has no storage. The adapter answers writes with `accept_unprocessed` and answers reads
  from the empty value (BLE-MIDI section 5).
- `Receiver::next` copies the packet, sends the GATT reply first, and then gives the UMPs to a synchronous sink. It
  never waits for the application, and it gives the other connection events back to the caller.
- `Sender::send` writes packets of at most ATT_MTU - 3 and N bytes with `notify_raw`. On `OutOfMemory` it waits
  2 ms and tries again.
- `request_link` asks for a connection interval of 7.5 ms to 15 ms and a data length of 251.

## Context

Versions in the crates.io index on 2026-10-22: `esp-radio` 0.17 uses `bt-hci` 0.6 (`trouble-host` 0.5.1),
`esp-radio` 1.0.0-beta.1 uses `bt-hci` 0.9 (`trouble-host` 0.7), and `trouble-host` 0.8 uses `bt-hci` 0.10, which
no `esp-radio` uses. The lessons of T-011 (docs/outstanding-tests.md) set the shape. In `trouble-host` 0.7 a full
GATT queue still drops the PDU (`post_gatt` gives `OutOfMemory`); the host now warns and counts it in `rx_errors`.
DEC-BLE-001 does not change.

## Consequences

`examples/esp32s3-ble-midi` uses the adapter with `esp-radio` 1.0.0-beta.1 and `esp-hal` 1.2, so it needs rustc 1.95
in the Espressif toolchain (CI job `esp32s3-example`). The Receiver keeps a copy of each packet (OPT-024).
`scripts/adapters-check.sh` checks the crate. A move to `trouble-host` 0.8 waits for an `esp-radio` on `bt-hci` 0.10.

## Alternatives

- The `gatt_server` and `gatt_service` macros: they give a fixed server type to the caller.
- One `run` loop with callbacks: `RequestConnectionParams` needs an async answer with the stack.
- `trouble-host` 0.8: no `esp-radio` uses `bt-hci` 0.10.
- `trouble-host` 0.5.1: the tested pair, but an old `trouble-host`.

## Verification

12 host tests of `zmidi-ble-trouble`, the bare-metal check and clippy in `scripts/adapters-check.sh`, the host
type-check of `examples/esp32s3-ble-midi/src/ble.rs` (`tests/example_ble.rs`), and T-016 on hardware.
