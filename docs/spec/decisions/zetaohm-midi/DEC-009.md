# DEC-009 — MIDI-CI API inferred from M2-101 roles; Function Block change split

**Status:** accepted

M2-101-UM defines messages, transactions and behaviour, not a programming
interface. The `zmidi-ci` API is inferred from the specification and follows
the sans-IO pattern of `zmidi-io` `Endpoint`:
- Responder: `receive` takes one MIDI-CI message (System Exclusive data) and
  gives the reply messages and the events for the application.
- Initiator: methods give the message to send (Discovery, Profile Inquiry,
  Set Profile On, Inquiry: Get Property Data framing, …); `receive` takes the
  replies.
- Values that only the device knows (for example the MIDI Message Report of
  9.7) are not held by the crate: an event asks for them, and a report writer
  puts the values the application gives into messages in the order of 9.7.1
  and 9.7.2.
- The caller gives random numbers for MUIDs (no RNG in no_std).
Each API rule in a module spec cites the M2-101 section it comes from.

Function Block changes (M2-101 3.3.1, 3.3.2) are split, with no dependency
between `zmidi-ci` and `zmidi-io`:
- `zmidi-ci`: a call such as `function_block_changed(block, random)` gives the
  Invalidate MUID message and takes a new MUID for that Function Block.
- `zmidi-io`: `Endpoint::function_block_notification(number)` gives the
  Function Block Info Notification of a block that did not change, also on a
  static endpoint (the notification M2-101 3.3.1 asks for after a MUID change;
  its name "Function Block Info Change Alert" does not exist in M2-104).
- The application calls both; the `midi` facade may add a helper later.

## Context

Questions: does the CI specification define the API, and where does the Function
Block change belong? `Endpoint::set_function_block` returns an error on a static endpoint,
but a MUID collision can happen there too.

## Consequences

- `zmidi-ci` depends on `zmidi-ump` only; `zmidi-io` does not depend on
  `zmidi-ci`.
- `zmidi-io` `Endpoint` gets one new method (a `/spec-edit` of Endpoint).
- M2-101 rows 3.3.1/05 (owner `zmidi-io`) and 3.3.2 (owner `zmidi-ci`) map to
  the two crates.
