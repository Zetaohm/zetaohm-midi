# DEC-018 — Word paths: a zmidi-ump Packet value carries UMPs between crates; typed Ump on top

**Status:** accepted

`zmidi-ump` gives `Packet`: the words of one UMP (at most 4) and its length, which is always the
Table 4 size of its Message Type. `Packet::from_words` checks the length; `Packet::words` gives the
slice; `Packet::ump` parses the typed `Ump` when a caller asks for it. Code that only moves UMPs works
on words and does not call `Ump::parse`, so a build that does not decode messages does not link it.

- `zmidi-io`: `BytesToUmp::push` and `BytesToUmpCore::push_with` give a `Pushed` whose items are
  `Packet` values; `UmpToBytes::write` writes bytes from the words (same API).
- `zmidi-ump`: `midi2_to_midi1` translates the words of one MIDI 2.0 Channel Voice packet into MIDI 1.0
  Channel Voice words (Appendix D.2); `to_midi1(&Ump)` stays and uses it.
- `zmidi-usb`: the Event Packet reader gives `Packet` values, and `Received::EventPacket` holds a
  `Packet`. `Received::ump` and `Received::words` stay.
- `zmidi-ci-pe`: `JsonWriter::number_u32` writes numbers that fit in 32 bits; the header writer uses it.

The typed API (`Ump`, the message structs, `to_midi1`, `Received::ump`) stays for callers that want it.

## Context

Words first, typed on top: step 3 of OPT-052 (OPT-015, DEC-017). The crates are 0.1.0 and not published, so a breaking
change costs little now. Prototypes (tools/size-probe/prototypes-2026-10-20.patch): BytesToUmp
5,428 -> 2,312 B, UmpToBytes 6,516 -> 2,328 B, to_midi1 7,268 -> 836 B, USB class -3,628 B, PE -992 B;
property tests showed the same output as the typed paths.

## Consequences

- Breaking: the item type of `Pushed`, the payload of `Received::EventPacket`, and the sink of
  `PacketReader::read_packet` change from `Ump` to `Packet`. Callers that want the typed value call
  `.ump()`.
- `Pushed` is about 44 B on a 32-bit target instead of 72 B.
- One translation implementation: `to_midi1` goes through `midi2_to_midi1`, so a property test
  compares the two forms on every input.

## Alternatives

- Word APIs beside the typed ones (push_words, read_words): rejected by the user; two APIs for each job.

## Verification

- Property tests: for random input, the word paths and the typed paths give the same UMPs and bytes
  (reader: random byte streams; writer and translation: random packets of every Message Type).
- `scripts/size-check.py`: the budgets of din_in, din_out, midi2_to_midi1 and usb_class go down to
  the new measurements.
