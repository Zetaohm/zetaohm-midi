# DEC-002 — All crates are no_std; the core API needs no alloc

**Status:** accepted

Every member crate is `#![no_std]` and builds for bare-metal targets
(STM32, ESP32, nRF).

The core API of each member does not need `alloc`:
- Fixed-size messages are values (`u32` to `u128` storage).
- To read multi-packet data (SysEx, Flex Data text, UMP Stream text), the API
  gives iterators or views over a borrowed `&[u32]` or `&[u8]`.
- To write multi-packet data, the caller gives the output buffer. A buffer
  that is too small gives an overflow error, never a panic.
- Messages that arrive one packet at a time are collected in fixed-capacity
  buffers (const generic `N`). A message larger than `N` gives an overflow
  error.

`alloc` is an optional, non-default Cargo feature for convenience functions
only (for example `String` or `Vec` return values). `std` is never necessary.

## Context

All Zetaohm targets are bare-metal microcontrollers, some without a heap.
A trial in the scratchpad confirmed that SysEx7 and Flex Data text can be
written, read and reassembled with no `alloc`, and that the code builds for
`thumbv7em-none-eabihf`.

## Consequences

- Dependencies must be `no_std` with `default-features = false`. The
  `thiserror` 1.x, `serde_json` and `rand::rng()` dependencies that exist now
  must be replaced or removed.
- Each member adds a gate that builds the library for a bare-metal target with
  no default features (for example `thumbv7em-none-eabihf`).
- Where a member cannot meet this rule (for example MIDI-CI Property Exchange
  JSON bodies), the member records an open question; it does not silently
  use `alloc`.

## Alternatives

- `alloc` in the core API: rejected. Some targets have no heap, and heap use
  in a real-time MIDI path is a timing risk.
- `std` support with a `no_std` subset: rejected. The primary targets are
  bare-metal.

## Verification

A gate in each member: `cargo check --lib --no-default-features --target
thumbv7em-none-eabihf`. The crate root has no `extern crate alloc` outside
`#[cfg(feature = "alloc")]`.
