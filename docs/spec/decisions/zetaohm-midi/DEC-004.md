# DEC-004 — Async embassy-ecosystem transport adapters; synchronous codecs

**Status:** accepted

Transport adapters (USB, BLE, UART) are async and use the embassy-ecosystem
traits from DEC-003.

Everything else is synchronous and has no embassy or executor dependency:
- all of `zmidi-ump`, `zmidi-ci` and `zmidi-file`;
- the codecs in `zmidi-io` (BLE-MIDI packets, UART byte stream, USB MIDI
  packets, UMP to MIDI 1.0 translation). (USB MIDI packets: in `zmidi-usb`
  since DEC-014, 2026-10-17. BLE-MIDI packets: in `zmidi-ble` since DEC-016,
  2026-10-18.)

Codecs are plain functions or state machines: data in, data out. Adapters
connect a codec to a transport and add no protocol logic.

## Context

The external stacks selected in DEC-003 (`embassy-usb`, `trouble-host`,
`embedded-io-async`) are async. The protocol logic must stay testable on the
host and usable from interrupt handlers or other executors.

## Consequences

- Codec tests run on the host with no executor and no hardware.
- A user with RTIC or a bare loop can use the codecs and write an own adapter.
- An adapter that contains protocol logic is a defect: move the logic into a
  codec.

## Alternatives

- All async: rejected. It ties every crate to an executor and makes host tests
  harder.
- All synchronous with blocking adapters: rejected. It does not fit the
  async external stacks.
