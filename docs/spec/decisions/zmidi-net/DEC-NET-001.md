The recommended option of each choice N-01 to N-60 in
the ambiguity register, "Decisions needed", "Open: zmidi-net requirement choices", as written in the requirements
that name this decision, and the readings of AMB-M2-124-01 to -60 that those requirements use.

- N-01: Receive window size W for duplicate and late Sequence Numbers? Accepted option: serial arithmetic (RFC 1982) with a bit map, W a const generic, default 64 (8 bytes for each session).
- N-02: Late Command (inside the window, not received before): deliver or drop? Accepted option: deliver it to the caller with a late mark.
- N-03: Receive state at session start and after Session Reset? Accepted option: H = 0xFFFF with H and the W numbers before it marked, so 0x0000 is the next expected number.
- N-04: Does the Client repeat Invitation after Invitation Reply: Pending? Accepted option: yes, as the 6.6 note says; a Pending timeout (default 60000 ms) starts at the first Pending.
- N-05: Invitation from a Client in Established Session: keep or reset the session? Accepted option: reply Accepted and keep all session state.
- N-06: What does a build without feature `auth` do with Command Codes 0x02, 0x03, 0x12, 0x13? Accepted option: the codes are always known, never NAK 0x01; Host: 0x02/0x03 from an address in Idle gets Bye 0x41, in other states NAK 0x02; Client: 0x12/0x13 get NAK 0x02.
- N-07: Sequence Number field of Retransmit Error? Accepted option: the oldest Sequence Number in the send history (Table 31), or the next number when the history is empty.
- N-08: Retransmit Request whose first number is held but a later one is not, or whose first number is not held? Accepted option: first number held: resend up to min(end, newest); first number not held: Retransmit Error only, no resend.
- N-09: UMP Data received around a Session Reset that this endpoint started? Accepted option: discard in Pending Session Reset only; after the Reply apply the normal Sequence Number rules from the start state.
- N-10: Late or extra Session Reset Reply in Established Session? Accepted option: ignore a Reply that comes within the Session Reset timeout after our own reset; else start a reset (6.12).
- N-11: Session Reset received while this endpoint is in Pending Session Reset? Accepted option: reply, reset, stay in Pending Session Reset until our Reply arrives.
- N-12: Form of the FEC idle payloads? Accepted option: sender uses Figure 19 (a new Zero Length Command in each idle payload); the receiver accepts Figure 18 and Figure 19.
- N-13: Command whose Payload Length goes past the end of the UDP payload? Accepted option: stop the read there, keep the Commands before it, send NAK 0x03.
- N-14: UMP Data Command with pl from 65 to 255? Accepted option: accept, no NAK.
- N-15: Reply when no section gives an action for a Command in a state? Accepted option: NAK 0x02 (Command Not Expected), no state change.
- N-16: Bye to an address with no session entry (0x05, 0x07, 0x40, 0x41, 0x45, 0x06): repeat it with a Pending Bye entry? Accepted option: one Bye for each received Command or UDP payload, no entry, no repeat.
- N-17: UMP Data, Retransmit Request or Retransmit Error in Pending Bye, and Retransmit Commands in Pending Session Reset? Accepted option: discard, no second Bye.
- N-18: Invitation Reply: Accepted or Pending at a Client in Pending Session Reset or Pending Bye? Accepted option: ignore.
- N-19: Bye Reason at the Invitation timeout? Accepted option: 0x80 (Invitation Canceled).
- N-20: Malformed Invitation? Accepted option: csd1 more than pl gives NAK 0x03; an empty name or id gives Bye 0x07.
- N-21: Repeat interval: default and range check? Accepted option: 500 ms; the configuration refuses values outside 300 ms to 2000 ms.
- N-22: Invitation timeout and Pending timeout? Accepted option: Invitation timeout 10000 ms, "none" permitted (6.4 "may"); Pending timeout 60000 ms.
- N-23: Session Reset timeout? Accepted option: 3000 ms.
- N-24: Bye timeout? Accepted option: 3000 ms, then Idle with no further Command.
- N-25: Host answer timeout (Host session in Pending Invitation or Authentication Required)? Accepted option: 60000 ms from the last Command of that Client, then Idle with no Command.
- N-26: Automatic Ping and session timeout rule? Accepted option: Ping interval 2000 ms (0 = off); end the session after 5 Pings with no reply (Bye 0x04).
- N-27: Number of open Pings kept for each peer? Accepted option: const generic P, default 8.
- N-28: NAK to an unsolicited or bad Ping Reply ("may")? Accepted option: configuration option, default off.
- N-29: Reply to a malformed NAK? Accepted option: ignore, never NAK a NAK.
- N-30: Who may write which Bye Reason? Accepted option: the writer checks the role (Table 27 group headings); the reader accepts all values.
- N-31: Maximum UDP payload of the writer? Accepted option: configurable, default 1400 bytes, no value above 1400.
- N-32: String field that is not valid UTF-8 or starts with a Byte Order Mark? Accepted option: accept, give bytes with a checked conversion.
- N-33: First idle interval T1 (at most 300 ms)? Accepted option: 100 ms.
- N-34: Further idle Commands? Accepted option: interval times G = 2, stop after K = 5.
- N-35: Retransmit Request timing? Accepted option: first delay D = 10 ms, doubled for each repeat, at most M = 3 requests, then a data-loss event and no Bye.
- N-36: Number of UMP Commands that the requester writes? Accepted option: the exact count up to H.
- N-37: Honour the Number of UMP Commands of a received request? Accepted option: yes (the "may ignore" of 7.2.3 is not used).
- N-38: Switch for Retransmit support? Accepted option: runtime configuration value, default on (not a Cargo feature).
- N-39: One send history for FEC and Retransmit? Accepted option: one shared ring of 32-bit words.
- N-40: Send history capacity C (32-bit words, for each session)? Accepted option: 512 words (2 KiB).
  Changed on 2026-10-18 (OPT-007): 256 words (1 KiB), about 1 KB less for each session.
- N-41: Queue of Retransmit Requests not served yet? Accepted option: const generic Q, default 4; a full queue ignores a new request.
- N-42: Host session capacity S? Accepted option: const generic, default 4.
- N-43: Sessions of one Client instance (one local UDP port)? Accepted option: const generic, default 1; never two sessions to one Host address.
- N-44: Host with both methods, Client sets D0 and D1? Accepted option: the method that the caller configures as preferred, default user authentication.
- N-45: Failed-authentication delay: counter scope, reset, limit? Accepted option: one counter for the Host, reset on success, 100 ms doubled, maximum 3200 ms; the Host ignores 0x02/0x03 while a delayed reply is due.
- N-46: After a failed digest: re-challenge or Bye? Accepted option: re-challenge (state 0x01) until a limit of failures in the session entry (default 5), then Bye 0x43 (or 0x44 for an unknown user).
- N-47: Host in Authentication Required receives the Command of the other method? Accepted option: a failed authentication of the method that it asked for.
- N-48: Host in Established Session receives the accepted 0x02/0x03 again (lost Accepted)? Accepted option: Accepted again if the digest is correct, else NAK 0x02.
- N-49: CryptoNonce byte outside 32 to 126 at the reader? Accepted option: accept and hash the bytes as received; the writer keeps the range.
- N-50: CryptoNonce from caller random bytes? Accepted option: 16 random bytes, byte = 32 + (b mod 95).
- N-51: CryptoNonce after a failed digest? Accepted option: the Host keeps the same nonce until Idle; the Client always uses the nonce of the last reply.
- N-52: How does the caller give credentials without alloc? Accepted option: a credentials provider passed to each call that needs a secret, a password lookup or a Username; the session keeps nonce (16 B), digest (32 B) and the Username in a fixed buffer (default 128 B), never the secret.
- N-53: Empty shared secret or password? Accepted option: error.
- N-54: Client caller declines to give credentials? Accepted option: Bye 0x80 (Invitation Canceled) and Pending Bye.
- N-55: Client Invitation timeout during authentication? Accepted option: start it again for each new CryptoNonce or Authentication State.
- N-56: Default Bye Reason when the Host caller rejects? Accepted option: 0x42 (Invitation Rejected: user did not accept session); the caller can give another one.
- N-57: Input of the PTR and SRV readers? Accepted option: the DNS message and the RDATA offset, so that name compression pointers work.
- N-58: TXT reader for an absent, empty or too long value? Accepted option: lenient: absent or empty gives "absent", long values are given as read.
- N-59: TTL above 60 seconds? Accepted option: refuse; default 60, range 1 to 60.
- N-60: Catalogue rows 6.4/26, 6.4/31, 6.5/10 (owner zmidi-ump): zmidi-net requirements? Accepted option: yes for the part that zmidi-net can check: map 6.4/26 and 6.5/10 to REQ-NET-DISC-011 and 6.4/31 to REQ-NET-DISC-012 (value types that accept only Notification-valid values and give the text back); the equality of the values stays device; change the catalogue owner to zmidi-net.

## Context

M2-124-UM v1.0.1 gives no timeout values, no sequence-number comparison and no rules for many error cases
(AMB-M2-124-01 to -60). Each choice had a recommendation below 90% confidence, checked against the specification
text and the open implementations (Microsoft Windows MIDI Services, libnetmidi2, Zephyr, amidi2net; register survey
of 2026-10-15).
