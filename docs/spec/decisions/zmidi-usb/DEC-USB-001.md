The recommended option of each choice U-01 to U-28 in
the ambiguity register, "Decisions needed", "zmidi-usb requirement choices", after two review rounds, as written in
the requirements that name this decision.

- U-01: How does the host reader test bcdMSC? Accepted option: exact values first, high byte as fallback with a report.
- U-02: Can the caller configure a function with no USB MIDI 2.0 Alternate Setting? Accepted option: yes; the writer then writes only Alternate Setting 0 (a plain USB-MIDI 1.0 device).
- U-03: Where does the rule that a Group Terminal is in one block only apply? Accepted option: in the whole Alternate Setting, for each direction.
- U-04: What does the reader do when a received length is not a multiple of 4? Accepted option: read the whole words or Event Packets, ignore the last 1 to 3 bytes, report an error; on USB MIDI 2.0 keep a held part of a UMP.
- U-05: What does the reader do with a UMP whose Group has no Group Terminal on that endpoint? Accepted option: the reader gives it with the mark "no Group Terminal"; the writer writes it with no change.
- U-06: What is the default endpoint configuration? Accepted option: one bulk MIDI OUT and one bulk MIDI IN endpoint, bInterval 0, wMaxPacketSize 64 at full speed and 512 at high speed (REQ-USB-MS2-009, REQ-USB-MS2-016).
- U-07: How strict is the writer about the block direction rule? Accepted option: the writer refuses all three; the reader reports them and keeps the descriptors.
- U-08: What does the writer do with a UMP that is longer than wMaxPacketSize? Accepted option: split it at word boundaries into consecutive packets.
- U-09: What is the default Group Terminal Block list? Accepted option: one bidirectional block, ID 0x01, Group Terminal 1 only, bMIDIProtocol 0x11, bandwidth 0x0000.
- U-10: Which wTotalLength does the writer put in the USB MIDI 1.0 MS Interface Header? Accepted option: the Appendix B value: the header, the Jacks, the Elements and all endpoint descriptors of Alternate Setting 0 (0x0041 in the example).
- U-11: How does REQ-USB-001 relate to the block writer? Accepted option: make the text of REQ-USB-001 narrower, to the M2-104 Appendix I strategy of one bidirectional Group Terminal Block with all 16 Groups; REQ-USB-GTB-010 is its writer check.
- U-12: Does the writer also put the Group Terminal Block descriptors inside Alternate Setting 1? Accepted option: no; only the request of section 6 gives them, and the reader skips inline ones. Test with macOS hardware before release 1.0.
- U-13: Does the crate write MIDI Element descriptors? Accepted option: the writer writes no Element; the reader reads Element descriptors.
- U-14: Does the crate write Transfer bulk endpoints? Accepted option: the writer writes none; the reader marks an endpoint with no MS_GENERAL descriptor as a Transfer endpoint.
- U-15: What does the writer do with unlisted bMIDIProtocol and bGrpTrmBlkType values? Accepted option: the writer refuses them.
- U-16: How lenient is the Group Terminal Block reader? Accepted option: accept a block descriptor with bLength 13 or more.
- U-17: Does the crate give a helper that makes Group Terminal Blocks from static Function Blocks? Accepted option: add it later, with the example firmware.
- U-18: Which CIN does the writer use for System Real Time? Accepted option: CIN 0xF (Table 4-2 example).
- U-19: Which UMP Group does a Cable Number use? Accepted option: fixed: cable n = Group n.
- U-20: Which UMP protocol does the Event Packet reader give? Accepted option: MIDI 1.0 Protocol UMPs (Message Type 0x2) by default, MIDI 2.0 (Message Type 0x4) as a caller option.
- U-21: How many cables does an endpoint have? Accepted option: a const generic from 1 to 16, default 1.
- U-22: Does the writer give an unparsed mode (all bytes in CIN 0xF packets)? Accepted option: yes, as an option with default off.
- U-23: What does the writer do with held SysEx bytes when a new status ends the SysEx? Accepted option: end the System Exclusive message with 0xF7 (CIN 0x5, 0x6 or 0x7 with the held bytes), then write the new message (REQ-USB-EVT-024).
- U-24: What does the host reader do with descriptor values that are not valid? Accepted option: lenient: report the error, give the value to the caller and continue.
- U-25: Which wMaxPacketSize values does the writer accept? Accepted option: refuse 0 and values that are not a multiple of 4, and values that USB 2.0 forbids for the bus speed (REQ-USB-MS2-016); default 64 at full speed, 512 at high speed.
- U-26: Which form does the Jack topology API have? Accepted option: a cable-count form (n_out, n_in, default 1 and 1) that gives the Appendix B topology and the TinyUSB Jack IDs 4k+1 to 4k+4, and also a full form where the caller gives each Jack.
- U-27: Does the writer need a string for each Jack? Accepted option: iJack 0 by default; the caller can give an index. The adapter crates and the example firmware give names.
- U-28: Who writes the Interface Association Descriptor (IAD) before the AudioControl interface? Accepted option: the USB stack or the adapter crate (embassy-usb writes it by default; usb-device has DescriptorWriter::iad()); no requirement in zmidi-usb.

## Context

The USB-MIDI class specifications give no action for many cases and conflict with their own examples
(AMB-USB-MIDI-2-01 to -41, AMB-USB-MIDI-1-01 to -31). Each choice was checked against the specification text and the
open implementations (TinyUSB, Linux snd-usb-audio and gadget, Windows MIDI Services, embassy-usb, usbd-midi, AmeNote;
register survey of 2026-10-17).
